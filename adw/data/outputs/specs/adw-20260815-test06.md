# Dark Mode Toggle in the Header

## Metadata
- issue_number: 3
- adw_id: adw-20260815-test06

## User Story
As a site visitor, I want a dark mode toggle button in the header, so that I can view the site in my preferred light or dark theme and have that choice remembered on my next visit.

## Scope
The site currently renders no header and has no theme state — the root layout emits only `<html>`/`<body>` around the page content, and the page shows two design-specimen cards whose light/dark styling is fixed per card. This feature adds a persistent site header containing a single toggle control that switches the overall site chrome (page background, header, and text) between a light and a dark theme, and persists the selected theme across reloads. Nothing beyond the theme switch and its persistence is in scope; the specimen cards keep their own fixed appearance and are not re-themed by this feature.

## Direction
After this feature exists:
- Every page renders a header at the top of the document, above the existing page content, and that header contains a theme toggle control.
- The document root carries an explicit theme state (light or dark) that the site chrome responds to; toggling the control flips that state and the visible appearance updates immediately without a reload.
- The selected theme is written to browser-local persistence under a stable key, so a reload or a return visit restores the last-chosen theme.
- On first paint, the persisted theme is applied before content is shown, so there is no flash of the wrong theme.
- With no stored preference, the site presents a defined default theme (light).
- The toggle control communicates its current state accessibly (e.g. an accessible label / pressed state reflecting the active theme).

## Use Cases
1. Given the site loaded with no stored preference / Input initial render / Expect the header is present and shows the theme toggle, and the site is in the default (light) theme.
2. Given the site in light theme / Input the visitor activates the toggle / Expect the document root reflects the dark theme and the site chrome updates immediately.
3. Given the site in dark theme / Input the visitor activates the toggle again / Expect the site returns to the light theme.
4. Given the visitor selected dark theme / Input reloading the page / Expect the site loads in dark theme from the persisted choice.
5. Given a persisted dark preference / Input the initial page load / Expect the dark theme is applied on first paint with no visible flash of the light theme.
6. Given the theme toggle / Input inspecting it in either theme / Expect it exposes an accessible label/state that reflects the currently active theme.

## Files
- `src/app/layout.tsx` — in scope to render the header above `children` and to establish/apply the root theme state (including applying the persisted theme before first paint).
- `src/app/globals.css` — in scope to define how the dark theme is expressed (dark variant / themed tokens) so the site chrome can respond to the root theme state.

### New Files
- `src/components/site-header.tsx` — the site header that hosts the theme toggle control.
- `src/components/theme-toggle.tsx` — the client-side toggle that reads/updates the active theme and persists the choice.

## Notes
- Persistence is browser-local under a single stable key; the builder chooses the key name and storage mechanism.
- The toggle and any theme-state reads that depend on the browser must run client-side; theme application on first paint must happen early enough to avoid a flash of the wrong theme.
- The two `DesignSpecimenCard` instances have intentionally fixed light/dark tokens and are out of scope — do not rewire them to follow the site theme.
